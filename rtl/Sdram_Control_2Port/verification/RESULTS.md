# 验证结果

日期：2026-10-15。

## 已通过

1. 原工程完整性：对生成前存在的 28 个工程文件逐一计算 SHA-256，内容均未修改。
2. 接口检查：新模块接口恰好等于原接口删除 WR2、RD2 后的集合，保留名称和顺序。
3. 实例检查：新控制器仅实例化一个写 FIFO 和一个读 FIFO，没有第二路信号、地址和调度分支残留。
4. 辅助模块对比：撤销独立命名后，五个辅助 Verilog 文件与原文件文本相同；参数头文件与原文件逐字节相同。
5. 核心时序对比：SDRAM 引脚生成及数据采样、读写传输状态机的源码段与原版本相同。
6. 使用 Vivado 2023.2 `xvlog` 以普通 Verilog 模式解析新版本全部六个 Verilog 文件，通过。
7. 新旧控制器、测试用 FIFO 模型和四组对比测试通过 SystemVerilog 编译及 `xelab` 展开，成功生成仿真快照。

## 对比测试内容

`tb_equivalence.sv` 提供四组长度：256、64、8、0。参考控制器的 WR2 固定关闭，RD2 长度为 0，和原工程的使用方式一致。

测试比较 SDRAM 控制/地址引脚、有效写数据、读端数据、FIFO 标志和数量、控制状态、地址更新；并检查每批数据数量、读优先、地址回绕、刷新、LOAD 和两次复位。

FIFO 使用相同的简化行为模型，读总线施加相同激励。这是删除第二路后的行为回归测试，不验证实际 Altera FIFO 的同步延迟、CDC 特性或真实 SDRAM 的电气时序。

## 保留的原实现告警

展开时原版与新版均出现 CMD 连接宽度（2 位接 3 位）、FIFO usedw 连接宽度（10 位接 16 位）及未连接 INIT_ACK 的告警。本次只删除未使用的两个端口，未调整这些原有定义。

静态检查可通过 `python verification/verify_sources.py` 重跑；仿真环境恢复后可通过 `verification/run_verification.ps1` 重跑对比测试。
